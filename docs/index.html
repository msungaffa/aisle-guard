Background

통로를 막는 물건은 사고가 나기 전엔
아무도 기록하지 않습니다.

AI 작업장 안전관리 시스템의 PoC 2(통로 장애물 감지)를, Jetson 대신 ESP32 한 대로 줄여 하루 만에 만든 버전입니다. 판정 기준을 정하고, 실측으로 검증하고, 기록으로 관리하는 품질관리 흐름을 보여 줍니다.

01

잠깐 둔 물건이 길을 막습니다

상자·가방이 비상 통로에 놓이면 대피·운반 동선이 막히지만, CCTV는 녹화만 하고 순찰 사이 공백에는 아무도 보지 않습니다.

02

사람과 물건을 구분해야 합니다

통로에는 사람도 지나갑니다. 움직이는 무언가를 모두 경고하면 오경보가 쌓여 결국 경고를 무시하게 됩니다.

03

서버 없이, 싸게 붙여야 합니다

구역마다 GPU 장비를 둘 수는 없습니다. 카메라가 달린 보드 하나가 촬영·추론·판정·경고를 모두 하고, 밖으로는 기록만 보냅니다.

과제 필수 조건

  • ① ESP32에 모델 탑재 — Edge Impulse FOMO를 Arduino 라이브러리로 넣고 보드에서 추론
  • ② 로그 DB 저장 — ESP32가 중간 서버 없이 Supabase REST로 직접 insert
  • ③ CI — push마다 판정 단위시험 · 펌웨어 컴파일 · 모델 품질 검사
How it works

보고, 판단하고, 알립니다

세 단계가 모두 보드 안에서 끝납니다. 네트워크가 끊겨도 경고는 바로 울리고, 기록은 다시 연결되면 보냅니다.

  1. 감지

    프레임마다 물체 위치를 찾습니다.

    • 96×96 RGB 입력, FOMO int8
    • obstacle · person 중심점과 점수
    • 한 번에 약 160ms

  2. 판단

    통로 안에 계속 있는 물건만 셉니다.

    • 점수 0.6 미만 · 통로 밖 · 사람 옆은 제외
    • 6프레임 중 4프레임이면 점유
    • 점유 10초면 경고

  3. 행동

    현장에는 LED, 기록은 DB로.

    • 관찰 1Hz · 경고 5Hz 깜빡임
    • warning · cleared · heartbeat
    • 방치 시간을 초 단위로 기록
Alert levels

잠깐 둔 물건은 지켜보고,
오래 둔 물건만 경고합니다

  • Level 0 정상통로에 물건 없음, 또는 사람만 지나감아무것도 하지 않음꺼짐
  • Level 1 관찰통로 안 물건이 6프레임 중 4프레임 이상 보임점유 시작 시각을 기억1Hz 깜빡임
  • Level 2 경고점유가 10초 넘게 계속됨warning 기록, 치우면 cleared와 방치 시간5Hz 깜빡임
예: 상자를 15초 두었다 치울 때2fps · 6프레임 시간 창

노란 칸 = 통로 안 물건이 보인 프레임. 방치 시간은 첫 "있음"부터 마지막 "있음"까지라, 점유 판정이 2초 늦게 나도 DB에는 실제 시간이 남습니다.

Hardware

추가 부품 없이,
엄지손가락만 한 보드 한 대

원래 기획은 RGB 카메라 6대와 Jetson 2대를 쓰는 구역 단위 시스템입니다. 이 과제는 통로 하나를 보드 하나로 줄였습니다.

  • 사용자 LED (GPIO 21)LOW가 켜짐. 1Hz 관찰 / 5Hz 경고
  • 2.4GHz Wi-Fi · USB-CSupabase HTTPS, PC와 시리얼 프레임

Decision logic · logic.cpp

모델이 낸 점 하나를,
경고 하나로 바꾸는 규칙

모델은 프레임마다 물체의 중심점과 점수만 냅니다. 물건마다 번호를 붙여 추적하지 않고, 통로 전체를 한 칸처럼 봅니다. 규칙은 Arduino에 기대지 않아 PC와 CI에서 같은 시험을 돌립니다.

  1. 점수 거르기

    흐린 화면의 약한 오검출을 버립니다.

    CONF_MIN 0.6

  2. 통로 안인가

    obstacle 중심점이 통로 다각형 안에 있어야 합니다. 선반 위 상자는 영역 밖이라 세지 않습니다.

    AISLE 꼭짓점 최대 8개, 시리얼 #AISLE로 설정

  3. 사람 옆은 보류

    사람의 옷·가방을 물건으로 잘못 본 경우를 대비해, 사람 가까이 있는 obstacle은 세지 않습니다.

    person_radius 16px

  4. 시간 창

    한두 프레임 놓치거나 튀어도 흔들리지 않게 최근 프레임을 모아 봅니다.

    WIN_N / WIN_K 6 / 4 · CLEAR_K 1

  5. 단계 올리기

    점유가 시작되면 관찰, 정해진 시간을 넘기면 경고하고 warning을 기록합니다.

    DWELL_T 10초 (시연용, 현장은 수 분)

  6. 해제와 방치 시간

    점유가 끝나면 cleared와 방치 시간(첫 "있음" ~ 마지막 "있음")을 기록합니다.

    DB에서 평균·최대 방치 시간 통계

단위시험이 지키는 것 · logic 18개 + proto 6개

  • 통로 밖 중심점은 세지 않는다
  • person은 세지 않는다
  • 점수 0.6 미만은 버린다
  • 한 프레임만 "있음"이면 점유가 아니다
  • 10초 미만은 Level 1, 이상은 Level 2
  • 해제 때 방치 시간이 ±1프레임 안에서 맞는다
  • 사람이 지나가는 시나리오에서는 경고가 없다
  • 깜빡이는 검출도 점유를 유지한다
  • 이벤트 JSON이 DB 컬럼과 맞고, 큐는 최근 20건을 지킨다

학습 방법

  1. 장면 만들기

    집에서 실제 통로를 만들기 어려워 AI로 생성한 창고 CCTV 클립 5개를 씁니다. 둔 시각·치운 시각을 알아 ±1초 검증이 됩니다.

  2. 자동 라벨 초안

    autolabel.py가 빈 통로와 다른 부분을 박스로 잡고, 150장 시트로 눈으로 확인합니다. 선반 위 상자는 라벨을 달지 않습니다.

  3. 학습·시험 나누기

    클립마다 마지막 30%를 시험 세트로 둡니다. 영상 프레임 105장으로 첫 모델 d1을 만들었습니다.

  4. 보드 화면 더하기

    보드 카메라가 찍은 화면 369장에, ECC 정렬로 찾은 영상 프레임의 박스를 옮겨 라벨을 붙입니다.

  5. int8로 보드에

    Edge Impulse에서 int8로 내보낸 Arduino 라이브러리를 펌웨어에 넣고 보드에서 시간을 잽니다.

  6. CI가 막기

    모델을 바꿀 때마다 model-gate가 같은 int8 모델을 시험 프레임에 돌려 재현율 0.9 아래면 실패시킵니다.

기록 시점

Level 2가 되는 순간 warning, 해제될 때 cleared, 1분마다 heartbeat. 프레임마다 저장하지 않습니다.

끊겨도 남깁니다

Wi-Fi가 끊기면 최대 20건을 메모리에 두었다가 다시 보냅니다. 경고 중 끊김 시험에서 누락 0건이었습니다.

쓰기만 허용

Scope

할 일과 하지 않을 일

합니다

  • 물건(obstacle)과 사람(person) 구분
  • 통로 영역 안 방치 시간 측정
  • LED 경고 (관찰·경고 두 속도)
  • 이벤트 DB 저장, 끊기면 보관 후 재전송
  • CI: 단위시험 · 컴파일 · 모델 게이트
  • 시연 화면 · DB 대시보드

하지 않습니다

  • 물건 종류 구분 (상자·가방 모두 obstacle)
  • 객체 추적 (번호 붙이기)
  • 낙상·화재 감지 (원래 기획의 PoC 1·3)
  • 여러 카메라 · 별도 서버
  • 사진 전송 · 얼굴 인식
